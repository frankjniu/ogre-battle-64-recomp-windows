# App architecture

`app/` is the CMake project that builds `ogrebattle64.exe`. It links the
recompiled game code, N64ModernRuntime (`librecomp`, `ultramodern`), RT64 and a
static SDL2.

## Source files (`app/src/`)

| file | what it does |
|---|---|
| `main.cpp` | entry point (`WinMain` forwarder), game registration, `update_gfx`, teardown, quick-load relaunch |

| `sdl_platform.cpp` | SDL init, window, input, error and thread-name callbacks, scripted taps, the live console |
| `audio_out.cpp` | the AI-buffer FIFO and the SDL output callback; `OGRE_AUDIO_*` |
| `renderer.cpp` | the RT64 renderer context, display-list diagnostics, captures |
| `rsp.cpp` | dispatch of the recompiled njpeg and audio microcodes; stub for any other task |
| `overlays.cpp` | base-section registration, `ogre_idle_wait` (the idle-thread hook) |
| `bank_overlays.cpp` | the 34 streamed bank units: registration, DMA-driven swap, `LOOKUP_FUNC` map, lookup check, scene forcing |
| `bank_funcs.inc` | the bank record table (generated by `make bank-recomp`, gitignored) |
| `launcher.cpp`, `ui.cpp`, `font.cpp` | the start screen and the tabbed panel it shares with the overlay |

## Runtime flow

1. `main.cpp` installs the crash logger, initialises SDL and resolves the
   config directory (the executable's folder; `OGRE_PREF_DIR` overrides it).
2. `recomp::register_game()` registers the entry: `entrypoint_address =
   0x80070C00`, `rom_hash = 0xbe6adaa5c3f8f7a9` (XXH3-64 of the big-endian ROM),
   save type SRAM, and an `on_init_callback` that registers the base sections
   and the bank units.
3. The start screen runs when no ROM is stored or a mod is installed.
   `recomp::select_rom` validates the ROM and stores a copy.
4. `recomp::start(cfg)` blocks the main thread. It starts the game thread and
   calls `update_gfx` in its loop; `update_gfx` pumps SDL events, draws the
   overlay, runs the per-frame hooks (cheats, hang watch, widescreen) and
   handles exit requests.
5. The game thread loads the base sections, DMAs the first 1 MB of ROM, and
   calls `recomp_entrypoint`, which clears BSS and runs the game's `main`.

## Runtime callbacks

| callback | source |
|---|---|
| `renderer_callbacks.create_render_context` | `renderer.cpp` (RT64 on D3D12 or Vulkan; `OGRE_GRAPHICS_API` pins it) |
| `rsp_callbacks.get_rsp_microcode` | `rsp.cpp` |
| `audio_callbacks` | `sdl_platform.cpp` → `audio_out.cpp` |
| `input_callbacks` | `sdl_platform.cpp` (keyboard and SDL GameController, through `input_map.cpp`) |
| `gfx_callbacks.update_gfx` | `main.cpp` |
| `error_handling_callbacks` | `sdl_platform.cpp` (message box, also writes `error.log`) |
| `threads_callbacks` | `sdl_platform.cpp` (thread names) |

## How game code meets the runtime

- **libultra is bridged by name.** `config/symbols/symbol_addrs.txt` names the
  game's libultra functions, and N64Recomp binds them to the runtime's
  `osXxx_recomp` implementations. Hardware access (VI, PI, SI, AI) goes through
  those.
- **Streamed code is swapped by DMA.** The game DMAs modules over each other at
  fixed RAM. `bank_overlays.cpp` maps the DMA's ROM range and RAM base to a bank
  record and loads its function table; calls into swappable RAM compile as
  `LOOKUP_FUNC` and resolve through that map (AGENTS.md rule 4).
- **Host behaviour inside a game function** is a `[[patches.hook]]` in
  `config/config.toml` or a bank config, which calls an `ogre_*` function in
  `app/src/`. Bank-code insertions that a hook cannot express are applied to the
  generated C by `tools/*.py` scripts that `make bank-recomp` runs.
